# Change: 统一外部数据源调用至 common 并按依赖封装

## Why
当前外部数据源调用分散在不同模块中，重复实现鉴权、重试、限流与日志，维护成本高且易引入不一致行为。

## What Changes
- 建立统一的外部依赖封装规范：所有第三方数据源客户端集中在 backend/common/{provider}/ 下。
- 每个外部依赖目录下封装我们可能用到的接口，形成清晰、可复用的 Client API。
- 统一横切策略：超时、重试、限流、缓存与结构化中文日志。
- 提供 Provider 注册表与工厂方法，支持通过配置选择数据源实现。
- 梳理并迁移现有分散调用到统一封装，减少重复代码。
- 保持对业务层的非破坏性接口适配，逐步替换内部调用路径。

## Impact
- 受影响的规范: specs/stock-data/spec.md
- 受影响的代码:
  - backend/common/eastmoney/*
  - backend/common/* 及其他直接调用外部 API 的模块
  - 配置与依赖注入位置（例如服务启动时的数据源选择）
