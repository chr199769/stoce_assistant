## 背景
当前预测链路主要聚焦历史形态相似度，缺少对公司关系、行业链路、政策事件影响的结构化理解，导致解释性不足、证据链松散。需要在现有行情与预测能力之上，引入知识图谱与多智能体协作架构，形成可追溯、可评估的预测链路。

## 目标 / 非目标
- 目标: 构建可查询的股票知识图谱并支撑预测推理
- 目标: 引入多智能体协作输出统一结论与证据链
- 目标: 提供可控的证据召回与冲突裁决策略
- 非目标: 替代现有行情数据源或重建全量行情存储
- 非目标: 引入闭源或内部依赖

## 决策
- 决策: 以公司、行业、事件、政策、资金流为核心实体构建图谱，保留可追溯证据来源
- 决策: 采用多智能体分工（基本面、事件、技术面、风险）并由协调智能体汇总
- 决策: 预测时使用“图谱关系扩展 + 事件时序检索 + 证据评分”的合成上下文
- 备选方案: 单一大模型直接输出预测，但可解释性弱且稳定性不足

## 风险 / 权衡
- 图谱数据质量不足可能导致推理偏差 → 增加来源标注与可信度评分
- 多智能体协作成本增加 → 使用可配置策略控制智能体数量与频率
- 事件抽取噪声增加 → 引入可信度阈值与降噪规则

## 约束
- 本次改动为系统性重构，尽量保证客户端功能不变
- 客户端与客户端相关接口不做大幅调整
- 后端服务允许大范围改动，可不向下兼容

## 迁移计划
- 先提供只读图谱查询与预测融合能力，再逐步替换既有预测解释输出
- 保持原预测接口兼容，通过新增字段提供增强信息
- 阶段一: 图谱只读查询 + 单轮预测融合 + 证据链展示
- 阶段二: 事件索引强化 + 可信度模型校准 + 指标监控上线
- 阶段三: 多智能体协作全量接入 + 冲突裁决优化 + 权重动态调整

## 知识图谱设计
### 最小闭环范围
- 实体: 股票、行业、事件、证据
- 关系: 股票-属于-行业、事件-影响-股票
- 事件: NEWS、POLICY、REPORT、RUMOR、CAPITAL
- 证据: 每条关系与事件必须绑定来源、时间戳与可信度
- 查询闭环: 以股票为入口可返回关联行业、关联事件与证据摘要

### 实体定义
- 股票、公司、行业、板块、事件、政策、宏观指标、资金流

### 关系定义
- 股票-属于-板块
- 公司-属于-行业
- 行业-受益-政策
- 事件-影响-股票
- 资金流-流入-股票

### 证据与可信度
- 每条关系记录来源、时间、可信度评分
- 可信度评分用于预测权重与冲突裁决

### 实体与ID策略
- 股票主键使用交易所+代码（如 SH:600519、SZ:000001）
- 公司主键使用标准化公司名称（全称优先），避免跨市场冲突
- 行业与板块使用标准化名称 + 版本号（如 SW:白酒:v2025）
- 别名映射规则:
  - 同义别名映射到同一主键（公司简称、旧名称、拼音）
  - 合并拆分记录变更历史，保留 from_id -> to_id 映射
  - 每条别名记录保留来源、时间与置信度
- 事件去重键由来源、时间窗、实体集合与类型组成

### 事件分类与规范
- 事件类型枚举与影响方向、强度标定规则
- 区分短期与中期影响，支持迟到数据回补与回溯修正

### 事件分类枚举
- NEWS: 新闻快讯、公告摘要、公司动态
- POLICY: 政策与监管变化、行业扶持、宏观政策
- REPORT: 财报与研究报告、评级调整
- RUMOR: 市场传闻与未证实消息
- CAPITAL: 资金流向与龙虎榜异动

### 事件去重键规则
- 目标: 同源重复消息在时间窗内幂等写入
- 格式: source|event_type|entity_id|time_bucket|content_fingerprint
- source: 事件来源渠道或抓取站点（标准化为小写）
- event_type: 事件分类枚举值
- entity_id: 主体实体ID（股票优先，其次行业/板块）
- time_bucket: 事件时间窗，按小时或天级截断
- content_fingerprint: 标题或摘要的哈希指纹
- 默认时间窗: T+1 天内去重，跨天视为新事件

### 关系强度与版本
- 区分统计强度与推理强度，来源与更新周期不同
- 关系与事件引入版本字段与更新时间

### 实体与关系 Schema（Neo4j）
- Entity 节点:
  - id: string
  - type: enum(EntityType)
  - name: string
  - attributes: json
  - created_at: timestamp
  - updated_at: timestamp
- Evidence 节点:
  - id: string
  - category: string
  - summary: string
  - confidence: int
  - source: string
  - timestamp: timestamp
- Relation 边:
  - type: enum(RelationType)
  - strength: float
  - evidence_id: string
  - created_at: timestamp
  - updated_at: timestamp
- Event 节点:
  - id: string
  - type: enum(EventType)
  - impact_direction: int
  - impact_strength: int
  - confidence: int
  - timestamp: timestamp
  - source: string
  - dedupe_key: string
  - created_at: timestamp
  - updated_at: timestamp
- 关系建模:
  - (Entity)-[:RELATION {type,...}]->(Entity)
  - (Entity)-[:HAS_EVENT]->(Event)
  - (Event)-[:HAS_EVIDENCE]->(Evidence)

## 知识图谱 RPC 服务设计
### 服务定位
- 独立 RPC 服务，负责图谱构建、查询、事件索引检索与证据聚合
- 对外仅提供只读查询接口，写入由内部任务或数据管道执行

### 接口列表
1. GetGraphNeighborhood
   - 作用: 按实体查询一阶或多阶关系网络
   - 请求: 实体类型、实体标识、关系过滤、层数、时间范围
   - 响应: 关系边、关联实体、关系强度、证据来源

2. GetEntityProfile
   - 作用: 获取实体摘要与关键指标
   - 请求: 实体类型、实体标识、时间范围
   - 响应: 实体基础信息、关联行业/板块、关键事件摘要

3. SearchEvents
   - 作用: 按实体或关键词检索事件
   - 请求: 实体标识、事件类型、时间窗口、最小可信度
   - 响应: 事件列表、影响方向、影响强度、证据来源

4. GetEvidenceBundle
   - 作用: 为预测请求聚合证据包
   - 请求: 股票代码、时间窗口、召回策略、证据上限
   - 响应: 结构化证据包、证据评分、证据覆盖率

5. GetRelationStrength
   - 作用: 查询实体间关系强度
   - 请求: 源实体、目标实体、关系类型
   - 响应: 关系强度、证据来源、更新时间

### 实现状态
- 已实现: GetGraphNeighborhood、GetEntityProfile、SearchEvents、GetRelationStrength

### IDL 结构建议
- Entity: id, type, name, attributes
- Relation: source, target, type, strength, evidence
- Event: id, type, entities, impact, confidence, timestamp, source
- Evidence: id, category, summary, confidence, source, timestamp
- EvidenceBundle: entities, relations, events, score, coverage

### 兼容与路由
- AI 服务通过 RPC 调用图谱服务获取证据包
- 网关不直接暴露图谱服务，仅由 AI 服务聚合后输出

## 数据接入与更新策略
### 接入来源
- 行情与成交量、新闻摘要、政策公告、财报摘要、资金流数据、公司披露信息

### 新闻源入库流程（阶段一）
- 拉取新闻源：按时间窗拉取新闻与公告列表
- 结构化解析：标题、正文、发布时间、来源、关联股票/行业
- 实体对齐：公司/股票名称映射为标准实体ID
- 事件抽取：映射到 EventType，计算影响方向与强度
- 证据生成：生成 Evidence(summary, source, timestamp, confidence)
- 去重写入：按 dedupe_key 去重后 Upsert 到图谱
- 指标回填：记录批次、来源与落库统计
- 入库源：东方财富个股新闻与公告，按配置股票列表拉取

- OpenBB: 开源金融数据平台，提供多数据源统一入口，适合做多市场扩展的聚合层
- GDELT: 全球新闻与事件开放数据，可用于政策/宏观事件补充

### 更新流程
- 日终批处理构建关系主干
- 盘中增量更新事件与资金流
- 事件过期策略：按时间窗口衰减影响力

### 数据血缘与追溯
- 为每条关系与事件记录来源与采集批次
- 支持按批次回滚与重新计算

## 事件时序索引
### 事件结构
- 事件类型、关联实体、影响方向、影响强度、来源可信度、时间戳

### 召回策略
- 以股票或板块为入口查询关联事件
- 优先召回高可信、短期事件
- 支持按事件类型白名单与黑名单过滤
- 事件时间窗固定为30天或90天，可信度阈值与上限可配置

### 索引与时间分桶策略（Neo4j）
- 事件节点索引: Event(timestamp) 使用范围索引提升时间窗检索
- 事件节点过滤: Event(type, confidence) 组合索引优化类型与可信度筛选
- 关系检索索引: RELATION(updated_at) 支持关系时间窗召回
- 去重约束: Event(dedupe_key) 唯一约束，确保同源事件幂等写入
- 时间分桶: 使用 TimeTree 节点（Year->Month->Day）并建立 Event-[:ON_DATE]->Day 关系
- 分桶策略: 天级分桶优先，支持按月或季度扩大范围查询

## 多智能体协作设计
### 智能体角色
- 基本面智能体：财务与估值
- 事件智能体：政策与新闻影响
- 技术面智能体：趋势与形态
- 风险智能体：波动、流动性与黑天鹅
- 协调智能体：聚合评分、冲突裁决与证据输出

### 角色输入证据边界
- 基本面智能体：财报摘要、估值指标、行业对比、公司公告摘要
- 事件智能体：政策/新闻事件、监管公告、事件证据摘要
- 技术面智能体：K线形态、技术指标摘要、量价结构、量化因子、筹码峰结构
- 风险智能体：异常波动、流动性、舆情负面与黑天鹅提示
- 协调智能体：只接收各角色结论与评分，不直接访问原始证据

### 协作流程
1. 召回证据：图谱关系扩展 + 事件检索
2. 角色分发：按角色拆分证据包
3. 并行评估：各智能体产出结论与评分
4. 冲突裁决：协调智能体输出最终方向与置信度
5. 证据汇总：输出结构化证据链

### 并行上限与超时规则
- 并行上限：同一请求最多 4 个智能体并行
- 单智能体超时：默认 60 秒，超时记为无输出
- 总链路超时：默认 90 秒，超过直接进入裁决降级
- 降级策略：缺失智能体的权重归零，并标记降级原因

### LangGraph 集成策略
- 编排节点：证据召回、角色分发、并行评估、冲突裁决、证据汇总
- 节点输入输出与中间状态全部写入 Langfuse
- 失败节点自动记录错误与回退策略

### 限流与重试策略
- 对外部模型调用加入指数退避重试与抖动
- 针对限流或可重试错误进行有限次重试
- 超过上限后返回部分结果与错误说明，避免整链路失败

### 冲突裁决策略
- 基于可信度与历史准确率加权
- 若冲突显著，强制输出冲突说明

### 可控并行与降级
- 设置并行上限、超时与熔断规则
- 支持最佳努力返回与降级路径
- 降级优先级: 事件智能体 > 技术面智能体 > 基本面智能体 > 风险智能体

### 离线标定
- 使用历史窗口进行校准与权重学习
- 更新默认参数并记录版本

### 离线校准流程
- 数据准备: 取历史预测记录（方向、置信度、证据覆盖率）与真实涨跌标签
- 分桶: 置信度按 10 桶划分，计算每桶准确率与样本占比
- 计算: ECE/ACE 与可靠性曲线
- 拟合: 对置信度做温度缩放或分段校准，生成校准函数
- 版本管理: 输出 weight_version、calibration_version 与生效时间窗
- 回放验证: 与上一个版本做对比评估，记录提升幅度

### 权重版本管理
- 权重配置文件带版本号与生效时间
- 每次调整记录来源数据窗口与指标变化

### 在线回传
- 预测结果与实际收益回传
- 触发权重与阈值的增量更新

## 证据与可信度模型
### 评分拆解
- 来源可信度、抽取可信度、时效权重

### 评分公式
- 事件置信度 = clamp(0, 100, 来源分 * 0.5 + 抽取分 * 0.3 + 时效分 * 0.2)
- 关系强度 = clamp(0.3, 0.8, 0.3 + 0.5 * 事件置信度 / 100)
- 证据置信度沿用事件置信度，支持按证据类型微调

### 默认权重与取值
- 来源分: 公告80、新闻70、其他60
- 抽取分: 标题长度>=15为60，低于15减5
- 时效分: 当前到事件时间每6小时衰减1分，最小40

### 冲突裁决公式
- 基于可信度、历史准确率与覆盖率加权
- 记录裁决中间量以支持复现

### 冲突裁决计算
- 输入: 各智能体方向dir∈{-1,0,1}、置信度conf∈[0,1]、历史准确率acc∈[0,1]、证据覆盖率cov∈[0,1]
- 归一权重: w = normalize(conf * 0.5 + acc * 0.3 + cov * 0.2)
- 加权得分: score = Σ(w_i * dir_i)
- 裁决方向: sign(score)，|score| < 0.1 视为“无明显方向”
- 冲突强度: conflict = 1 - |score|

### 中间量记录
- agent_weights: 每个智能体的 w_i
- agent_scores: 每个智能体的 w_i * dir_i
- final_score: score
- conflict_strength: conflict

## 已决策默认值
- 最小闭环范围: 股票、公司、行业、板块、事件、政策、资金流；关系覆盖“属于/影响”
- 权重策略: 基本面0.25、事件0.25、技术面0.30、风险0.20，可配置范围0.10到0.40
- 事件强度标定: 影响方向为正负，强度区间0到100，可信度参与加权
